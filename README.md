# Rock Exotica Enforcer для Android

Запись усилия с динамометров Rock Exotica Enforcer по Bluetooth LE.

## Что умеет

* пока только медленный режим для статики - с динамикой буду разбираться
  при случае;
* должно работать с 4 динамометрами одновременно, но пока тестировал только
  с двумя (список приборов появляется только когда их больше одного);
* чтение заводской калибровки из самого прибора;
* живое значение, пик с удержанием, программный ноль, kN или кгс;
* график с прореживанием по минимумам и максимумам — вершины рывков
  не срезаются; несколько приборов рисуются в одних осях своими цветами;
* старт / пауза / стоп, сохранение в CSV, отправка файла («Поделиться»);
* **крупное табло** — число во весь экран, читается издалека; при нескольких
  приборах экран делится поровну;
* **сигнал по порогу** — зуммер и вибрация при превышении заданного усилия.

CSV: `timestamp, t_sec, serial, label, counts, kN`. Все приборы пишутся
в один файл по общей оси времени — колонки `serial` и `label` показывают,
чей отсчёт. `counts` - это сырые отсчёты АЦП.

## Совместимость

| | |
|---|---|
| minSdk | **21** (Android 5.0) |
| targetSdk | 34 |
| Язык | Kotlin, JVM-таргет 1.8 |
| Зависимости | только `androidx.appcompat` и `androidx.core` |

Минимизированы требования к версиям:

* **никаких графических библиотек** — график рисуется своим `PlotView` на
  `Canvas`. Одинаково на всех версиях, ноль зависимостей;
* **никакого `java.time`** — даты через `SimpleDateFormat`, иначе на API 21
  понадобился бы десугаринг;
* **разрешения разведены по версиям**: до Android 11 включительно — старые
  `BLUETOOTH*` плюс `ACCESS_FINE_LOCATION`, с Android 12 — `BLUETOOTH_SCAN`
  с флагом `neverForLocation` и `BLUETOOTH_CONNECT`;
* на Android 6…11 приложение проверяет, включена ли служба геопозиции: без неё
  скан BLE **молча** не находит ничего, и это самая частая причина «не видит
  прибор»;
* вызовы API 26/31/33 (`VibrationEffect`, `VibratorManager`,
  `writeCharacteristic(char, value, type)`) вынесены в отдельные методы
  с проверкой версии — старые устройства до них просто не доходят;
* `connectGatt` с `TRANSPORT_LE` начиная с API 23: без этого часть стеков
  пытается подключиться по BR/EDR и не находит сервисов;
* файлы пишутся в каталог приложения (`getExternalFilesDir`) — разрешения
  на хранилище не нужны ни на одной версии.

## Сборка

Wrapper (`gradlew`) в репозитории не лежит — это бинарный `.jar`.
Любой из способов ниже создаёт его сам или обходится без него.

### Android Studio

Открыть папку `enforcer_android` (File → Open). Студия сама синхронизирует
проект, при необходимости создаст wrapper и подтянет SDK 34.
Дальше Run ▶ на подключённом телефоне или Build → Build APK(s).

### Из командной строки

Нужны JDK 17 и Android SDK (platform 34, build-tools 34).

```bash
cd enforcer_android
gradle wrapper          # один раз, создаст gradlew
./gradlew assembleRelease
```

APK окажется в `app/build/outputs/apk/release/`.

### GitHub Actions

`.github/workflows/android.yml` собирает APK на каждый push и кладёт его
в артефакты сборки (вкладка Actions → нужный запуск → Artifacts →
`Enforcer`, внутри `Enforcer.apk`). Локально ставить ничего не нужно.

Workflow сам находит проект по `settings.gradle`, поэтому работает и когда
`enforcer_android` — корень репозитория, и когда он лежит подпапкой.

### Установка

APK подписан отладочным ключом, а не ключом из Play, поэтому телефон
попросит разрешить установку из этого источника. Настройки → приложение-установщик →
«Разрешить установку неизвестных приложений».

## Как пользоваться

1. Включить прибор(ы), убедиться, что на экране горит значок Bluetooth
   (если нет — удержать SAMPLE).
2. «Найти». Знакомые приборы подключаются по адресу за секунду, эфир при
   этом не сканируется вовсе. Сканирование включается, только если кто-то
   из знакомых не отозвался или знакомых нет: тогда 10 секунд поиска,
   и подключается всё найденное.
3. Дождаться в строке состояния `калибровка: a=… z=…` — это значит, что
   параметры калибровки прочитаны из прибора, а не взяты запасные.
4. «Ноль» — если нужно обнулить вес снаряжения, висящего на приборе.
5. «Старт» → испытание → «Стоп» → «Сохранить».

Единицы переключаются тапом по подписи рядом с числом или через меню. Имя
файла записи, ширина окна графика и порог сигнала — в меню (три точки).

Кнопки «Ноль» и «Сброс пика» внизу действуют на все приборы сразу. Когда
приборов несколько, у каждого в своей строке есть ещё и собственные.

### Несколько приборов

Меню **«Приборы…»** показывает подключённые и знакомые в одном списке.
По нажатию на прибор — подключить, отключить или забыть. Оттуда же
«Искать новые»: поиск в эфире, минуя знакомые адреса.

Знакомые приборы нужны не для удобства. Отключённый от приложения Enforcer
уходит в направленную рекламу и в поиске не виден — подключиться к нему
можно только по запомненному адресу. Приложение помнит до шести приборов.

Предел в четыре прибора взят с запасом: сколько параллельных BLE-соединений
потянет телефон, зависит от его стека, на слабых бывает меньше. Лишнее
соединение просто не встанет, и в журнале будет строка.

### Если прибор не находится

**После разрыва связи Enforcer в поиске не виден.** Он переходит на
направленную рекламу, адресованную прежнему хозяину: сканеру такие пакеты
не показываются, а прямое подключение по адресу они допускают. Поэтому
приложение сперва пробует запомненный адрес напрямую и только потом ищет.

Если и это не помогло — переподключите Bluetooth на самом приборе:
удержать SAMPLE (значок погаснет), удержать ещё раз (загорится). Тогда он
вернётся в общий эфир и найдётся сканированием.

Случай, когда это неизбежно, ровно один: **первое подключение после
переустановки приложения**. Переустановка стирает настройки вместе
с запомненным адресом, и достучаться до прибора нечем.

Прочие причины «не вижу прибор», по частоте:

* на Android 6…11 выключена служба геопозиции — скан BLE тогда **молча**
  не находит ничего. Приложение это проверяет и предупреждает;
* прибор занят другим подключением: он принимает только одно;
* поиск запускали чаще пяти раз за полминуты — Андроид глушит скан
  без всякого сообщения. В журнале про это есть строка.

### Что важно знать про прибор

* **Каждый прибор принимает только одно подключение.** Пока к нему подключён
  ноутбук или другой телефон, этот не подсоединится. Разных приборов это
  не касается — их можно вести одновременно.
* **Частота по радио — 2 Гц**, в любом режиме. Заявленные 500 выборок
  в секунду живут только во внутренних записях прибора и по Bluetooth
  не транслируются.
* **Первые 0,6 с после подключения отбрасываются.** Пока телефон не был
  подключён, вывод копится в приборе и вываливается разом — это хвост
  прошлой сессии.
* **Ноль на приборе (POWER+FORCE) сдвигает калибровку.** Если нажать после
  подключения, прочитанная калибровка устареет - надо переподключаться.
* **Поверх работающего потока приложение прибору ничего не шлёт** — команда
  в этот момент роняет отклик прибора по радио. Поэтому температура
  читается один раз, при подключении, и в динамике её нет.
* **Номер прибора выводится из серийника:** три последние цифры.
  `20030466` → `466` → `1D2`.

## Устройство кода

| Файл | Что делает |
|---|---|
| `Link.kt` | парк приборов и всё общее: поиск, журнал, запись, очередь GATT, CSV. Живёт дольше активности, поэтому поворот экрана и переход на табло не рвут соединения |
| `Device.kt` | один прибор: соединение, разбор потока, своя калибровка и отсчёты |
| `MainActivity.kt` | основной экран, меню, разрешения, сохранение и отправка |
| `BigActivity.kt` | крупное табло |
| `PlotView.kt` | график, до шести кривых в одних осях |
| `Alarm.kt` | зуммер и вибрация по порогу |

Вся работа с GATT идёт в одном фоновом потоке; интерфейс раз в 200 мс
читает готовые поля.

Последовательность команд при подключении собрана из шагов
(`Wait` / `Write` / `Run`) и выполняется по одному. Очередь **одна на всё
приложение**, а не своя у каждого прибора: Android разрешает одну
незавершённую операцию GATT на процесс, а не на соединение. Подключения при
этом начинаются одновременно, последовательными оказываются только опросы
при настройке — они короткие, так что четыре прибора выходят в поток
за десяток секунд.

У каждой записи есть сторож на 4 секунды: без него цепочка встала бы молча,
если прибор не подтвердит запись. Шаги отключившегося прибора выбрасываются
из очереди — писать больше некуда.
